# Breakout Radar — A&R Intelligence Engine
### Autonomous Discovery, Multi-Platform Acoustic Telemetry & Explainable Artist Evaluation

---

## 1. Executive Summary & Product Overview

**Breakout Radar** is an enterprise-grade Artist & Repertoire (A&R) intelligence platform engineered specifically for record labels, scouts, independent distributors, and music publishing houses. While legacy music intelligence suites (such as Chartmetric, Soundcharts, or Viberate) primarily track established superstars who have already broken into the global mainstream, Breakout Radar solves the fundamental **A&R Alpha Problem**: discovering high-potential, raw, and emerging artists *before* commercial tipping points occur.

### The Core Problem Solved
Traditional A&R relies heavily on manual club scouting, subjective word-of-mouth, or trailing social media vanity metrics (which are frequently contaminated by artificial bot streams, paid influencer campaigns, or legacy popularity). Breakout Radar inverts this paradigm by combining:
1. **Autonomous Periodic Scraping & Discovery**: Scanning emerging music catalogues, streaming engines, and open metadata registries on configurable scheduled loops (30 or 60 minutes) across targeted regions (anchored in East Africa) and genres.
2. **Aggressive Superstar Filtering**: A strict exclusion filter (`isLegacyMainstream`) that purges established superstars (e.g., Diamond Platnumz, Burna Boy, Wizkid, Sauti Sol, Rayvanny) so analysts focus 100% of their operational bandwidth on genuine unsigned or independent talent.
3. **The 4-Pillar Artistic Value Model (AVM)**: A psychoacoustic and structural musicology evaluation framework that analyzes isolated audio stems, vocal pitch holding accuracy ($\pm 20¢$ tolerance), multilingual lyrical code-switching arcs, dynamic track loudness jumps (+6.2 dB hook lifts), and studio polish headroom.
4. **"Dive In" Executive Telemetry**: An interactive data intelligence dashboard delivering 8 core growth KPIs and 10 bespoke D3.js vector visualizations (spanning 90-day stream trajectories, platform audience concentrations, daily engagement anomalies, and organic retention corridors).
5. **A&R Committee Decision Pipeline**: A 5-tier recommendation workflow (PURSUE, MEET, WATCH, MORE EVIDENCE, HOLD) with side-by-side candidate comparison, advance valuation modeling ($USD), and cloud-synchronized decision ledgers.

### `src/services/avmEngine.ts`
- **Purpose**: Rigorous mathematical engine implementing the complete Artistic Value Model (AVM) specification.
- **Key Equations & Implementations**:
  - **Single Track AVM ($TAV$)**:
    $$TAV = 100 \times (w_V \cdot P_V + w_W \cdot P_W + w_S \cdot P_S + w_C \cdot P_C) + PB$$
    Where $P_V$ is Vocal Ability, $P_W$ is Writing & Concept, $P_S$ is Song as a Whole, $P_C$ is Composition & Arrangement, and $PB$ is the capped studio production bonus ($0.0 \le PB \le 3.0$).
  - **Artist Catalog Rollup ($AAV$)**:
    $$AAV = 0.50 \cdot \text{Median}(TAV) + 0.20 \cdot P_{75}(TAV) + 0.15 \cdot \text{Consistency} + 0.15 \cdot \text{Trajectory}$$
    Where $\text{Consistency} = \max(0, 100 - 2 \cdot \sigma)$ and $\text{Trajectory}$ is the linear regression slope over the last 5 releases.
  - **Pillar Sub-Score Breakdown**:
    - $P_V$: Range & tessitura fit ($S_{V1}$), pitch accuracy within $\pm 20¢$ ($S_{V2}$), tone & vocal identity ($S_{V3}$), and dynamic control ($S_{V4}$).
    - $P_W$: Lyric imagery ($S_{W1}$), narrative arc ($S_{W2}$), hook memorability ($S_{W3}$), and multilingual code-switching ($S_{W4}$).
    - $P_S$: Dynamic energy curve fit ($S_{S1}$), structural coherence ($S_{S2}$), emotional resonance ($S_{S3}$), and repeatability index ($S_{S4}$).
    - $P_C$: Melodic contour ($S_{C1}$), harmonic progression ($S_{C2}$), rhythm & groove ($S_{C3}$), and stem arrangement balance ($S_{C4}$).

## 5. Security, Data Integrity & Threat Modeling

Breakout Radar enforces defense-in-depth across the client and cloud boundaries:

1. **Client-Side Secret Isolation**: No backend database credentials, private API keys, or administrative tokens are ever embedded in client-side code bundles. Public configuration (such as the Firebase Web Client API Key) is restricted exclusively to authorized domains via Google Cloud Identity and Google Cloud Console settings.
2. **Hardened Firestore Security Rules (`firestore.rules`)**:
   - Explicit collection-level validation rules for `/artists`, `/decisions`, `/discoveryScans`, and `/settings`.
   - Mandatory field verification (`id`, `name`, `discoveryScore`, `decisionMaker`).
   - Default-deny rule (`allow read, write: if false;`) applied to all unspecified database paths to eliminate unauthorized data traversal.
3. **Cross-Site Scripting (XSS) Defenses**: All external string inputs (such as track titles, artist bios, and Wikipedia extracts) are safely sanitized and rendered using React’s standard escaping mechanisms. No arbitrary `dangerouslySetInnerHTML` directives are utilized without strict sanitization.
4. **Defensive API Rate Limiting & Quota Management**: Autonomous scans utilize sequential request pacing (minimum 1.0s between catalogue requests) and respect upstream provider rate limits (e.g., Apple Music, MusicBrainz).
5. **Data Resilience & Offline Tolerance**: The system operates with dual-layer persistence: immediate local browser caching (`localStorage`) combined with asynchronous cloud synchronization (`Firebase Firestore`). Network latency or temporary connectivity drops never freeze the user interface or discard scout evaluations.

### Prerequisites
- **Node.js**: Version 18.x, 20.x, or 22.x LTS
- **Package Manager**: npm (v9+), pnpm, or bun

### Local Development Setup
1. Clone the repository to your local workstation:
   ```bash
   git clone <repository-url> breakout-radar
   cd breakout-radar
   ```
2. Install all required dependencies:
   ```bash
   npm install
   ```
3. Prepare your environment variables:
   ```bash
   cp .env.example .env
   ```
   *(Ensure `APP_URL` and `GEMINI_API_KEY` are provided if integrating server-side Gemini features).*
4. Start the local Vite development server:
   ```bash
   npm run dev
   ```
   *The application will boot and be accessible at `http://localhost:3000`.*

### Production Build & Preview
To compile the production-ready distribution package:
```bash
npm run build
```
*The optimized output will be generated in `/dist`.*

To preview the production build locally:
```bash
npm run preview
```

### Deploying Firestore Security Rules
When deploying or modifying security rules for the project's Firestore database:
```bash
firebase deploy --only firestore:rules
```

## 11. Mathematical Formulation & Psychoacoustic Reference Guide

The **Artistic Value Model (AVM)** is formalized as a rigorous four-pillar system that isolates intrinsic musicality from studio production polish.

### 11.1 Pillar 1: Vocal Ability ($P_V$)
$$P_V = 0.25 \cdot S_{V1} + 0.35 \cdot S_{V2} + 0.20 \cdot S_{V3} + 0.20 \cdot S_{V4}$$
- **$S_{V1}$ (Tessitura & Range Utilization)**: Evaluates whether the artist sings within their natural acoustic comfort zone without strain.
- **$S_{V2}$ (Pitch Holding Accuracy)**: Calculated via CREPE fundamental frequency extraction:
  $$\text{Pitch Accuracy} = \frac{\sum_{t=1}^{T} \mathbb{I}(|\Delta f_0(t)| \le 20\text{ cents})}{T_{\text{voiced}}}$$
  Where frames held within $\pm 20$ cents represent pure in-key musicality.
- **$S_{V3}$ (Vocal Timbre & Harmonic Richness)**: Ratio of harmonic energy to inharmonic noise, defining recognizable vocal texture.
- **$S_{V4}$ (Dynamic Micro-Expression)**: Decibel breath control and expressive articulation between soft verses and belt hooks.

### 11.2 Pillar 2: Writing & Concept ($P_W$)
$$P_W = 0.30 \cdot S_{W1} + 0.25 \cdot S_{W2} + 0.25 \cdot S_{W3} + 0.20 \cdot S_{W4}$$
- **$S_{W1}$ (Metaphorical Density)**: Presence of unique sensory imagery versus generic pop clichés.
- **$S_{W2}$ (Narrative Cohesion)**: Progression of storytelling between verses and payoff in the outro.
- **$S_{W3}$ (Hook Memorability)**: Syllabic repetition, phonetic rhythm, and catchiness of the central motif.
- **$S_{W4}$ (Multilingual Code-Switching)**: In East Africa, authentic fluid transitions between Swahili, Sheng, and English representing street-level cultural resonance.

### 11.3 Pillar 3: Song as a Whole ($P_S$)
$$P_S = 0.35 \cdot S_{S1} + 0.25 \cdot S_{S2} + 0.20 \cdot S_{S3} + 0.20 \cdot S_{S4}$$
- **$S_{S1}$ (Energy Curve Concordance)**: Correlation between instantaneous loudness and expected emotional trajectory, with time-to-first-hook $\le 18$ seconds.
- **$S_{S2}$ (Section Lift)**: Minimum $+4.0\text{ dB}$ to $+7.0\text{ dB}$ RMS loudness jump entering the chorus hook.
- **$S_{S3}$ (Emotional Resonance)**: Harmonic tension and resolution balance across the track arc.
- **$S_{S4}$ (Organic Repeat Replay Factor)**: Measured catalog replay ratio ($>3.0\times$ repeat listens per unique user).

### 11.4 Pillar 4: Composition & Arrangement ($P_C$)
$$P_C = 0.30 \cdot S_{C1} + 0.25 \cdot S_{C2} + 0.25 \cdot S_{C3} + 0.20 \cdot S_{C4}$$
- **$S_{C1}$ (Melodic Contour)**: Stepwise motion balance versus leap intervals in the lead melody.
- **$S_{C2}$ (Harmonic Interest)**: Chord progression complexity, secondary dominants, and modal interchange.
- **$S_{C3}$ (Groove & Syncopation)**: Micro-timing offset and polyrhythmic swing in the drum/percussion stems.
- **$S_{C4}$ (Frequency Space Distribution)**: Separation between bass, vocal, drum, and melodic stems preventing acoustic mud.

## 12. Disaster Recovery, Backups & Rollback Runbook

### 12.1 Local Cache Recovery
If an A&R scout experiences unexpected browser crashes:
1. Breakout Radar automatically commits all evaluations to `localStorage` under `breakout_radar_real_artists` and `breakout_radar_decisions`.
2. Reloading the browser immediately restores all in-progress reviews, active filters, and decision history.

### 12.2 Firestore Cloud Restoration
1. Cloud backups are automatically captured through Firebase Cloud Firestore point-in-time recovery (PITR).
2. To export a snapshot of all active decisions:
   - Navigate to the **Recommend** section -> Click **Export Pipeline Ledger (JSON)**.
   - Or navigate to **Dive In** -> Click **Export Dossier (JSON)**.

### 12.3 Rollback Deployment Procedure
If an issue occurs in production:
1. Revert to the last stable Git commit:
   ```bash
   git checkout <last-stable-commit-hash>
   npm install
   npm run build
   ```
2. Redeploy the static distribution assets to Cloud Run or hosting provider.
3. If Firestore security rules need rollback:
   ```bash
   git checkout HEAD~1 firestore.rules
   firebase deploy --only firestore:rules
   ```
